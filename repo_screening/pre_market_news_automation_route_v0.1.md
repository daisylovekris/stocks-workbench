# 盘前消息自动化路线｜v0.1

## 一、路线结论

当前盘前消息自动化 v0.1 推荐路线：

1. 先用 daily_stock_analysis 跑通 0 成本盘前摘要。
2. Horizon 作为主工具，负责 RSS 聚合、AI 摘要、去重、定时简报与推送。
3. feedgrab 作为信息源补充层，负责微信财经公众号、RSS 源补充、付费墙财经媒体与社媒线索采集。
4. DailyBrief 只读参考，用于借鉴 GitHub Actions 定时架构和 HTML 报告结构。
5. opennews-mcp 排除，不进入小工坊主线。

## 二、工具分工

### 1. daily_stock_analysis

定位：
- 当前 0 成本盘前摘要候选；
- 可优先试跑；
- 用于验证每日多股巡检、新闻异动、技术摘要和推送提醒是否能服务股票小工坊。

使用边界：
- 不自动交易；
- 不生成实盘买卖指令；
- 不接券商；
- 只用于盘前摘要和持仓观察。

### 2. Horizon

定位：
- 盘前消息自动化主工具候选。

用途：
- RSS 聚合；
- 财经新闻摘要；
- 新闻去重；
- 中文摘要；
- 定时简报；
- 推送；
- 外围消息整理。

使用边界：
- 不使用 AI 评分生成买卖判断；
- 不把摘要当最终结论；
- 试跑前先验证财经 RSS 源可用性；
- 只作为消息线索源和简报生成工具。

### 3. feedgrab

定位：
- Horizon 的信息源补充层。

用途：
- 微信财经公众号抓取；
- RSS 源补充；
- 付费墙财经媒体线索；
- 社媒/网页内容采集；
- 输出 Markdown + YAML 原始材料。

使用边界：
- 不作为主工具；
- 不生成买卖建议；
- 不配置高风险权限；
- 后续若试跑，仅限只读信息源采集。

### 4. DailyBrief

定位：
- 只读参考。

可借鉴：
- GitHub Actions 定时简报；
- HTML 单文件报告；
- 外围 ticker 技术分析结构。

不作为主工具原因：
- 无 A 股个股支持；
- 无 A 股公告/行业新闻；
- 无 Telegram/邮件/Webhook 推送；
- TypeScript 栈与当前小工坊不直接兼容。

### 5. opennews-mcp

定位：
- 排除。

排除原因：
- 核心偏加密市场；
- A 股覆盖不足；
- AI 评级与 Trading Signal 风险较高；
- 容易制造交易幻觉；
- 外围宏观消息继续使用 Perplexity 交叉验证即可。

## 三、盘前消息自动化 v0.1 目标

目标不是自动给买卖建议，而是生成盘前检查草稿。

盘前检查应覆盖：

- 公司公告；
- 个股新闻；
- 行业催化；
- 外围市场；
- 板块情绪；
- 资金/融资相关新闻；
- 是否有新增公告级重大利空；
- 是否有新增短线催化。

## 四、推荐输出格式

每日生成一个 Markdown 文件：

stocks/news_briefings/YYYY-MM-DD_pre_market_brief.md

内容包括：

1. 今日重点关注标的；
2. 公司公告；
3. 行业新闻；
4. 外围市场；
5. 个股突发；
6. 风险提示；
7. 需要 Perplexity 交叉验证的问题；
8. 结论草稿。

## 五、验证流程

固定流程：

1. 工具先抓取新闻与公告线索；
2. 生成盘前消息草稿；
3. 交给 Perplexity 做外部交叉验证；
4. 再由人工判断是否写入个股卡片或当日计划；
5. 不让任何工具直接输出买卖动作。

## 六、后续行动

第一阶段：
- 继续使用 daily_stock_analysis 作为 0 成本试跑候选。

第二阶段：
- 验证 Horizon 的财经 RSS 源可用性。

第三阶段：
- 测试 feedgrab 是否能稳定抓取微信财经公众号与 RSS 原始材料。

第四阶段：
- 将盘前消息摘要接入 Telegram 或小工坊日报。

## 七、纪律

- 不自动交易；
- 不接券商；
- 不配置高风险权限；
- 不使用 long/short 信号；
- 不使用 AI 评分替代判断；
- 不把新闻摘要当事实终局；
- 所有重大信息必须多源验证。
