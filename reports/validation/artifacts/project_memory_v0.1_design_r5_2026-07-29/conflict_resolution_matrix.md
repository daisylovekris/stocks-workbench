# Conflict resolution matrix

The matrix preserves all 15 r4 scenarios. Memory records conflicts and fails closed; it does not resolve business authority by synthesis.

| scenario | primary_authority | conflict_condition | memory_evidence_status | allowed_wording | forbidden_inference | required_evidence | validator_expectation |
|---|---|---|---|---|---|---|---|
| `rules_vs_code` | Current committed governing rule | Rule text and implementation behavior differ at the selected snapshot | `implementation_conflict` | “The committed rule governs permission; implementation divergence is recorded.” | Code grants a permission absent from the rule | Exact inventory-bound rule and implementation paths, commits, and raw hashes | Both identities are present; status is exactly `implementation_conflict`; no permission is inferred from code |
| `closure_vs_later_code` | Current applicable committed rule and implementation for present behavior | A closure artifact predates a later implementation or rule change | `stale_closure` | “The closure is historical; the later rule or implementation is linked separately.” | Historical closure proves the later code | Exact closure identity plus exact later rule or implementation identity and chronology | Commit chronology is checked; closure cannot establish post-closure behavior |
| `official_data_summary_conflict` | Canonical `data/daily/*_facts.json` | A summary, card, review, weekly note, or index differs from official facts | `blocked_data_conflict` | “Canonical official facts are primary; the conflicting summary is retained in its own class.” | A summary substitutes for or rewrites official facts | Exact official-facts identity and every conflicting source identity | Canonical facts are present; conflict remains explicit; downstream conclusion is blocked |
| `current_cards_cross_scope_difference` | Each current card within its declared scope | Current cards differ because they describe different scopes | `current` | “Each card is separately current within its stated scope.” | Cards are merged into a synthetic state | Exact identities of all cards plus their stated scopes | Scopes are explicit and non-overlapping; no synthetic merge is emitted |
| `current_cards_same_scope_conflict` | Competing current cards pending adjudication | Two current cards claim the same scope and disagree | `adjudication_required` | “Same-scope current-card conflict requires adjudication.” | Either card is selected automatically | Exact identities of every competing same-scope card | Same scope is detected; status is `adjudication_required`; no winner is chosen |
| `daily_review_cross_class_difference` | Dated Daily Review within its class and the other source within its own class | Daily Review differs from a card, weekly source, or other class without sharing authority scope | `current` | “The dated Daily Review and the other class are separately current in scope.” | Daily Review becomes current-card or official-data authority | Exact Daily Review identity and exact identity of the other class | Date and class are explicit; cross-class difference is not treated as supersession |
| `daily_review_same_scope_conflict` | Competing dated Daily Reviews pending adjudication | Two Daily Reviews claim the same date and scope and disagree | `adjudication_required` | “Same-scope Daily Review conflict requires adjudication.” | A review is chosen by filename date or recency alone | Exact identities of all competing reviews with date and scope | Same date and scope are checked; no automatic selection occurs |
| `weekly_cross_class_difference` | Dated weekly observation within its class and the other source within its own class | Weekly observation differs from a card, review, or index without conflicting with canonical facts | `current` | “The weekly observation remains separately dated and current within its scope.” | Weekly observation becomes a trading instruction or current-card authority | Exact weekly identity and exact identity of the other class | Date and class remain explicit; no trading conclusion is generated |
| `weekly_official_facts_conflict` | Canonical `data/daily/*_facts.json` | Weekly text or table differs from canonical official facts | `blocked_data_conflict` | “Canonical official facts are primary; weekly observation is blocked on the data conflict.” | Weekly content overrides official facts | Exact official-facts and weekly identities | Facts are present; blocked status is emitted; no derived conclusion proceeds |
| `index_source_divergence` | Underlying repository source referenced by the index | `stock_workbench_index.md` is behind or differs from its source | `stale` | “The index is stale; the underlying source remains primary.” | The navigation index resolves or overwrites its source | Exact index identity and exact underlying source identity | Index is marked stale and cannot resolve source content |
| `agent_raw_summary_conflict` | Raw run output together with bound metadata | An A/B comparison, review summary, or derived note differs from raw output or metadata | `adjudication_required` | “Raw, metadata, and summary conflict requires adjudication.” | Summary proves an unrecorded result or silently replaces raw output | Exact raw-output, metadata, and summary identities | Raw and metadata are both bound; conflict remains visible; run is not generalized |
| `planned_vs_implemented` | Explicit implementation and validation evidence | A plan claims or implies completion without required implementation or validation evidence | `pending_evidence` | “Planned only; implementation or validation is not evidenced.” | Planned work is rendered as implemented, validated, or closed | Exact plan identity and any claimed implementation, test, validation, and sealing identities | Required evidence is checked against status; incomplete claims fail closed |
| `chat_only_observation` | None until repository evidence exists | An assertion or result appears only in chat | `pending_evidence` | “Pending observation; repository evidence is absent.” | Chat establishes benchmark, status, model identity, or authority | Exact later repository identity if one is created; chat text is not formal evidence | Chat-only content is excluded from formal seeds and conclusions |
| `missing_path` | None for the absent object | A cited repository path does not exist at the selected snapshot | `path_missing` | “The requested evidence path is missing at the selected snapshot.” | Absence supports the requested claim | Exact requested relative path and selected commit | Missing path produces `path_missing`; validation fails closed |
| `superseded_authority` | Explicitly named successor | A predecessor differs from a source that explicitly declares succession | `superseded` | “The predecessor is historical; the successor relation is explicit.” | A later date alone establishes supersession | Exact predecessor and successor identities plus an explicit relationship | Successor relation is required; recency alone never changes authority |
