# 复盘链路连续文档更新规则｜v0.1

## 一、规则定位

本文件用于约束股票小工坊中“连续演化文档”的更新方式。

适用对象包括但不限于：

- 日复盘；
- 总索引；
- 低位观察卡；
- 持仓观察卡；
- 风险与跟踪卡；
- 估值与安全边际卡；
- 加仓分析卡；
- 周观察计划；
- 后续新增的连续跟踪类文档。

本规则的核心目的：

- 避免只新增最新日期小节，却遗漏当前状态区；
- 避免历史口径残留在当前判断区；
- 避免把观察条件写成买卖动作；
- 避免旧价位身份、旧确认链条、旧小标题继续误导后续更新；
- 让小工在更新连续文档时具备自适应检查能力。

## 二、基本原则

### 1. 历史小节保留，当前框架必须更新

历史日期小节中的历史事实可以保留。

例如：

- 06-29 小节可以继续写“下探 145 后强修复”；
- 06-29 小节可以继续写“157 盘中突破但未站稳”；
- 06-29 小节可以继续写“160 仍未收回”。

但如果最新交易日已经是 06-30，当前判断区就必须升级为最新口径。

例如：

- 153—155 已连续维持；
- 157 已收盘站上；
- 160 盘中突破但未收盘确认；
- 150 未跌破；
- 145—150 未进入；
- 145 未触及。

不能让 06-29 的当前口径残留成 06-30 的当前判断。

### 2. 新增日期小节不等于完成更新

每次更新连续文档时，不能只新增一个日期小节。

必须同时检查并同步：

- 当前状态；
- 当前结论；
- 当前观察重心；
- 当前背景；
- 当前操作影响；
- 风险提示；
- 持仓观察框架；
- 机动仓风险观察触发；
- 三种估值情景；
- 重新评估区；
- 分层观察区间；
- 不能直接加仓；
- 当前纪律；
- 小标题；
- 底部本卡结论。

## 三、必须扫描的区域

连续文档更新后，必须扫描以下区域是否仍残留旧日期、旧价位、旧确认链条。

### 1. 顶部当前状态区

常见名称：

- 当前状态；
- 当前口径；
- 当前结论；
- 当前观察状态；
- 当前持仓观察状态；
- 当前估值观察状态；
- 当前加仓评估状态。

### 2. 底部总结区

常见名称：

- 本卡结论；
- 本卡当前结论；
- 当前纪律；
- 当前持仓策略；
- 当前操作影响；
- 后续观察重点。

### 3. 中段长期框架区

常见名称：

- 三种估值情景；
- 分层观察区间；
- 重新评估区；
- 当前最值得观察的重新评估区；
- 什么时候不能补一手；
- 什么时候可以重新评估补一手；
- 当前不能直接加仓的情况；
- 可以进入重新评估加仓逻辑的情况；
- Top 5 风险；
- 风险提示；
- 持仓观察框架。

### 4. 标题和小标题

必须检查标题本身是否残留旧口径。

常见问题：

- `153—155 能否连续维持`；
- `153—155 重新收回并连续维持`；
- `157 重新站回并维持`；
- `160 能否收回`；
- `145—150 盘中进入但收盘离开`；
- `下探 145 后强修复`。

如果这些标题已经不是最新交易日的当前主矛盾，必须升级标题。

例如 06-30 后应改成：

- `153—155 能否继续作为修复支撑`；
- `157 能否继续维持`；
- `160 能否收盘站上并连续确认`。

## 四、价位身份必须随最新交易日更新

### 1. 盘中突破、收盘站上、连续维持必须严格区分

禁止混写：

- 盘中突破 ≠ 收盘站上；
- 收盘站上 ≠ 连续维持；
- 连续维持 ≠ 趋势完全重启；
- 盘中触及 ≠ 已打开；
- 收盘离开 ≠ 永久解除风险。

示例：

06-30 阳光电源：

- 160：盘中突破 160.26，但收盘 159.02，未收盘确认；
- 157：已收盘站上；
- 153—155：已连续维持；
- 150：未跌破；
- 145—150：未进入；
- 145：未触及。

不能写成：

- 160 已收回；
- 趋势完全重启；
- 风险解除；
- 低位风险永久解除。

### 2. 关键价位身份示例

以 06-30 为例：

| 价位 / 区间 | 当前身份 | 禁止误写 |
|---|---|---|
| 153—155 | 已连续维持，后续看能否继续作为修复支撑 | 仍写“能否重新收回” |
| 157 | 已收盘站上，后续看能否继续维持 | 仍写“能否重新站回” |
| 160 | 盘中突破但未收盘确认 | 写成“160 已收回 / 已确认” |
| 150 | 未跌破，不是硬底 | 写成“150 是硬底” |
| 145—150 | 未进入，风险缓和但未永久解除 | 写成“风险永久解除” |
| 145 | 未触及，不是硬底 | 写成“145 是硬底” |
| 138.61 | 员工持股均价心理锚 | 写成硬底或独立判断依据 |

## 五、观察条件不得写成执行动作

股票小工坊只做复盘、观察、风险识别、估值分析和加仓评估条件分析。

禁止输出即时买卖建议。

禁止正向写：

- 可以加仓；
- 应该加仓；
- 适合加仓；
- 加仓条件成熟；
- 减 1 手；
- 处理 1 手；
- 优先处理；
- 开始评估机动仓；
- 立即处理仓位；
- 买入 / 卖出 / 追涨 / 抄底。

如需保留观察含义，必须改成：

- 加仓评估条件改善；
- 仍不前置；
- 风险观察权重上升；
- 需要重新评估；
- 本卡不输出即时处理动作；
- 仅作为观察条件，不构成执行动作。

## 六、不同卡片的特殊规则

### 1. 低位观察卡

重点检查：

- 150 是否被写成硬底；
- 145 是否被写成硬底；
- 145—150 是否被写成风险永久解除；
- 低位风险缓和是否被写成风险解除；
- 补一手相关内容是否变成动作建议。

正确写法：

- 低位风险继续缓和，但未永久解除；
- 150 / 145 不是硬底；
- 145—150 今日未进入，不等于风险永久消失；
- 本卡只做观察，不输出即时处理动作。

### 2. 持仓卡

重点检查：

- 浮亏是否更新；
- 当前收盘价是否更新；
- 持仓观察框架是否从旧阶段升级；
- 是否残留“分批减仓 / 处理仓位”等动作化表达。

正确写法：

- 本节仅记录持仓观察框架，不输出即时仓位处理动作；
- 风险观察权重上升；
- 需要重新评估。

### 3. 风险与跟踪卡

重点检查：

- 风险缓和是否被写成风险解除；
- 机动仓处理触发是否被写成动作建议；
- 文件定位里的“持仓处理触发条件”是否需要改成“持仓风险观察触发条件”。

正确写法：

- 风险继续缓和，但不是风险解除；
- 机动仓风险观察触发；
- 本卡不输出即时处理动作。

### 4. 估值与安全边际卡

重点检查：

- 安全边际观察改善是否被写成安全边际充分确认；
- 估值修复是否被写成估值重估确认；
- 三种估值情景是否仍停留在旧收盘价；
- 当前操作影响区是否残留旧确认链条。

正确写法：

- 安全边际观察继续改善，但不是估值风险解除；
- 不是估值重估确认；
- 仍需 Q2 / Q3 财务数据、储能毛利率、海外订单兑现、现金流、应收账款、存货继续验证。

### 5. 加仓分析卡

重点检查：

- 加仓评估条件改善是否被写成可以加仓；
- 加仓评估条件继续改善是否被写成加仓条件成熟；
- 小标题是否残留旧阶段；
- 重新评估区、分层观察区间、不能直接加仓区是否同步到最新交易日。

正确写法：

- 加仓评估条件继续改善，但 160 未收盘确认前仍不前置；
- 153—155 已连续维持，后续看能否继续作为修复支撑；
- 157 已收盘站上，后续看能否继续维持；
- 160 盘中突破但未收盘确认；
- 仍不前置；
- 本卡不输出买卖动作。

## 七、旧口径残留自查清单

更新完成后，必须在当前判断区搜索以下旧口径。

如果出现在历史日期小节中，可以保留。

如果出现在当前框架、当前标题、当前结论中，必须修正。

常见旧口径：

- 下探 145 后强修复；
- 153—155 已重新收回，但需连续维持；
- 153—155 能否连续维持；
- 153—155 重新收回；
- 157 盘中突破但未站稳；
- 157 能否重新站回；
- 160 仍未收回；
- 160 能否收回；
- 145—150 盘中进入但收盘离开；
- 145 精准触及但未跌破；
- 当前浮亏约 -14.01%；
- 收盘 155.64；
- 量比 1.09；
- 安全边际观察改善，但未确认；
- 加仓评估条件改善，但仍不前置。

## 八、每次更新后的强制自查

每次更新连续文档后，必须输出自查结果：

1. 是否只修改指定文件；
2. 是否新增最新日期小节；
3. 是否同步当前状态区；
4. 是否同步底部本卡结论；
5. 是否同步中段长期框架；
6. 是否同步小标题；
7. 是否清理旧日期 / 旧价位 / 旧确认链条；
8. 是否清理动作化表达；
9. 是否保留历史小节事实不乱改；
10. 是否没有输出买卖建议；
11. 是否没有读取 `.env` / token / key / secret；
12. 是否没有做 git 操作，除非任务明确要求。

## 九、git 前全链审计要求

在进入 git add / commit / push 前，必须做全链只读审计。

审计对象通常包括：

- `stock_workbench_index.md`
- 当日日复盘文件；
- 低位观察卡；
- 持仓卡；
- 风险与跟踪卡；
- 估值与安全边际卡；
- 加仓分析卡。

全链审计必须确认：

- 核心事实一致；
- 价位身份一致；
- 当前定性一致；
- 禁止表达只出现在否定语境；
- 没有旧口径残留在当前框架；
- 没有动作化表达；
- 没有 token / key / secret；
- 没有范围外文件改动。

## 十、规则版本说明

v0.1 来源于 2026-06-29 与 2026-06-30 阳光电源复盘链路实战。

典型问题包括：

- 新增日期小节正确，但底部本卡结论仍停留旧日期；
- 当前状态更新了，但中段条件区没更新；
- 正文更新了，但小标题仍是旧确认链条；
- 风险缓和被误写成风险解除；
- 盘中突破被误写成收盘确认；
- 观察条件被写成处理仓位动作；
- 估值观察改善被误写成估值重估确认；
- 加仓评估改善被误写成加仓条件成熟。

后续如出现新型错误，应继续追加到本规则。
