# 复盘链路连续文档更新规则｜v0.1

## 一、规则定位

本文件用于约束股票小工坊中“连续演化文档”的更新方式。

适用对象包括但不限于：

- 日复盘；
- 总索引；
- 低位观察卡；
- 持仓观察卡；
- 风险与跟踪卡；
- 估值与安全边际卡；
- 加仓分析卡；
- 周观察计划；
- 后续新增的连续跟踪类文档。

本规则的核心目的：

- 避免只新增最新日期小节，却遗漏当前状态区；
- 避免历史口径残留在当前判断区；
- 避免把观察条件写成买卖动作；
- 避免旧价位身份、旧确认链条、旧小标题继续误导后续更新；
- 让小工在更新连续文档时具备自适应检查能力。

## 二、基本原则

### 1. 历史小节保留，当前框架必须更新

历史日期小节中的历史事实可以保留。

例如：

- 06-29 小节可以继续写“下探 145 后强修复”；
- 06-29 小节可以继续写“157 盘中突破但未站稳”；
- 06-29 小节可以继续写“160 仍未收回”。

但如果最新交易日已经是 06-30，当前判断区就必须升级为最新口径。

例如：

- 153—155 已连续维持；
- 157 已收盘站上；
- 160 盘中突破但未收盘确认；
- 150 未跌破；
- 145—150 未进入；
- 145 未触及。

不能让 06-29 的当前口径残留成 06-30 的当前判断。

### 2. 新增日期小节不等于完成更新

每次更新连续文档时，不能只新增一个日期小节。

必须同时检查并同步：

- 当前状态；
- 当前结论；
- 当前观察重心；
- 当前背景；
- 当前操作影响；
- 风险提示；
- 持仓观察框架；
- 机动仓风险观察触发；
- 三种估值情景；
- 重新评估区；
- 分层观察区间；
- 不能直接加仓；
- 当前纪律；
- 小标题；
- 底部本卡结论。

## 三、必须扫描的区域

连续文档更新后，必须扫描以下区域是否仍残留旧日期、旧价位、旧确认链条。

### 1. 顶部当前状态区

常见名称：

- 当前状态；
- 当前口径；
- 当前结论；
- 当前观察状态；
- 当前持仓观察状态；
- 当前估值观察状态；
- 当前加仓评估状态。

### 2. 底部总结区

常见名称：

- 本卡结论；
- 本卡当前结论；
- 当前纪律；
- 当前持仓策略；
- 当前操作影响；
- 后续观察重点。

### 3. 中段长期框架区

常见名称：

- 三种估值情景；
- 分层观察区间；
- 重新评估区；
- 当前最值得观察的重新评估区；
- 什么时候不能补一手；
- 什么时候可以重新评估补一手；
- 当前不能直接加仓的情况；
- 可以进入重新评估加仓逻辑的情况；
- Top 5 风险；
- 风险提示；
- 持仓观察框架。

### 4. 标题和小标题

必须检查标题本身是否残留旧口径。

常见问题：

- `153—155 能否连续维持`；
- `153—155 重新收回并连续维持`；
- `157 重新站回并维持`；
- `160 能否收回`；
- `145—150 盘中进入但收盘离开`；
- `下探 145 后强修复`。

如果这些标题已经不是最新交易日的当前主矛盾，必须升级标题。

例如 06-30 后应改成：

- `153—155 能否继续作为修复支撑`；
- `157 能否继续维持`；
- `160 能否收盘站上并连续确认`。

## 四、价位身份必须随最新交易日更新

### 1. 盘中突破、收盘站上、连续维持必须严格区分

禁止混写：

- 盘中突破 ≠ 收盘站上；
- 收盘站上 ≠ 连续维持；
- 连续维持 ≠ 趋势完全重启；
- 盘中触及 ≠ 已打开；
- 收盘离开 ≠ 永久解除风险。

示例：

06-30 阳光电源：

- 160：盘中突破 160.26，但收盘 159.02，未收盘确认；
- 157：已收盘站上；
- 153—155：已连续维持；
- 150：未跌破；
- 145—150：未进入；
- 145：未触及。

不能写成：

- 160 已收回；
- 趋势完全重启；
- 风险解除；
- 低位风险永久解除。

### 2. 关键价位身份示例

以 06-30 为例：

| 价位 / 区间 | 当前身份 | 禁止误写 |
|---|---|---|
| 153—155 | 已连续维持，后续看能否继续作为修复支撑 | 仍写“能否重新收回” |
| 157 | 已收盘站上，后续看能否继续维持 | 仍写“能否重新站回” |
| 160 | 盘中突破但未收盘确认 | 写成“160 已收回 / 已确认” |
| 150 | 未跌破，不是硬底 | 写成“150 是硬底” |
| 145—150 | 未进入，风险缓和但未永久解除 | 写成“风险永久解除” |
| 145 | 未触及，不是硬底 | 写成“145 是硬底” |
| 138.61 | 员工持股均价心理锚 | 写成硬底或独立判断依据 |

## 五、观察条件不得写成执行动作

股票小工坊只做复盘、观察、风险识别、估值分析和加仓评估条件分析。

禁止输出即时买卖建议。

禁止正向写：

- 可以加仓；
- 应该加仓；
- 适合加仓；
- 加仓条件成熟；
- 减 1 手；
- 处理 1 手；
- 优先处理；
- 开始评估机动仓；
- 立即处理仓位；
- 买入 / 卖出 / 追涨 / 抄底。

如需保留观察含义，必须改成：

- 加仓评估条件改善；
- 仍不前置；
- 风险观察权重上升；
- 需要重新评估；
- 本卡不输出即时处理动作；
- 仅作为观察条件，不构成执行动作。

## 六、不同卡片的特殊规则

### 1. 低位观察卡

重点检查：

- 150 是否被写成硬底；
- 145 是否被写成硬底；
- 145—150 是否被写成风险永久解除；
- 低位风险缓和是否被写成风险解除；
- 补一手相关内容是否变成动作建议。

正确写法：

- 低位风险继续缓和，但未永久解除；
- 150 / 145 不是硬底；
- 145—150 今日未进入，不等于风险永久消失；
- 本卡只做观察，不输出即时处理动作。

### 2. 持仓卡

重点检查：

- 浮亏是否更新；
- 当前收盘价是否更新；
- 持仓观察框架是否从旧阶段升级；
- 是否残留“分批减仓 / 处理仓位”等动作化表达。

正确写法：

- 本节仅记录持仓观察框架，不输出即时仓位处理动作；
- 风险观察权重上升；
- 需要重新评估。

### 3. 风险与跟踪卡

重点检查：

- 风险缓和是否被写成风险解除；
- 机动仓处理触发是否被写成动作建议；
- 文件定位里的“持仓处理触发条件”是否需要改成“持仓风险观察触发条件”。

正确写法：

- 风险继续缓和，但不是风险解除；
- 机动仓风险观察触发；
- 本卡不输出即时处理动作。

### 4. 估值与安全边际卡

重点检查：

- 安全边际观察改善是否被写成安全边际充分确认；
- 估值修复是否被写成估值重估确认；
- 三种估值情景是否仍停留在旧收盘价；
- 当前操作影响区是否残留旧确认链条。

正确写法：

- 安全边际观察继续改善，但不是估值风险解除；
- 不是估值重估确认；
- 仍需 Q2 / Q3 财务数据、储能毛利率、海外订单兑现、现金流、应收账款、存货继续验证。

### 5. 加仓分析卡

重点检查：

- 加仓评估条件改善是否被写成可以加仓；
- 加仓评估条件继续改善是否被写成加仓条件成熟；
- 小标题是否残留旧阶段；
- 重新评估区、分层观察区间、不能直接加仓区是否同步到最新交易日。

正确写法：

- 加仓评估条件继续改善，但 160 未收盘确认前仍不前置；
- 153—155 已连续维持，后续看能否继续作为修复支撑；
- 157 已收盘站上，后续看能否继续维持；
- 160 盘中突破但未收盘确认；
- 仍不前置；
- 本卡不输出买卖动作。

## 七、旧口径残留自查清单

更新完成后，必须在当前判断区搜索以下旧口径。

如果出现在历史日期小节中，可以保留。

如果出现在当前框架、当前标题、当前结论中，必须修正。

常见旧口径：

- 下探 145 后强修复；
- 153—155 已重新收回，但需连续维持；
- 153—155 能否连续维持；
- 153—155 重新收回；
- 157 盘中突破但未站稳；
- 157 能否重新站回；
- 160 仍未收回；
- 160 能否收回；
- 145—150 盘中进入但收盘离开；
- 145 精准触及但未跌破；
- 当前浮亏约 -14.01%；
- 收盘 155.64；
- 量比 1.09；
- 安全边际观察改善，但未确认；
- 加仓评估条件改善，但仍不前置。

## 八、每次更新后的强制自查

每次更新连续文档后，必须输出自查结果：

1. 是否只修改指定文件；
2. 是否新增最新日期小节；
3. 是否同步当前状态区；
4. 是否同步底部本卡结论；
5. 是否同步中段长期框架；
6. 是否同步小标题；
7. 是否清理旧日期 / 旧价位 / 旧确认链条；
8. 是否清理动作化表达；
9. 是否保留历史小节事实不乱改；
10. 是否没有输出买卖建议；
11. 是否没有读取 `.env` / token / key / secret；
12. 是否没有做 git 操作，除非任务明确要求。

## 九、git 前全链审计要求

在进入 git add / commit / push 前，必须做全链只读审计。

审计对象通常包括：

- `stock_workbench_index.md`
- 当日日复盘文件；
- 低位观察卡；
- 持仓卡；
- 风险与跟踪卡；
- 估值与安全边际卡；
- 加仓分析卡。

全链审计必须确认：

- 核心事实一致；
- 价位身份一致；
- 当前定性一致；
- 禁止表达只出现在否定语境；
- 没有旧口径残留在当前框架；
- 没有动作化表达；
- 没有 token / key / secret；
- 没有范围外文件改动。

## 十一、2026-07-01 新增审计规则｜标题层级、条件句升级、估值便宜幻觉、字段人工校验

v0.2 来源于 2026-07-01 阳光电源复盘链路全链审计。

### 1. 标题层级也必须审计

连续文档更新时，不只检查正文事实，还必须检查标题层级与章节结构。

需要重点扫描：

- 新增日期小节后，是否突然出现旧主体标题；
- 是否出现类似 `## 二、当前结论先行` 这种旧结构标题嵌在新日期小节后方；
- 小标题是否仍停留在上一交易日口径；
- 当前状态标题与正文结论是否不一致；
- 全局章节物理位置是否容易造成"日期小节嵌套旧结构"的视觉错觉。

处理原则：

- 若标题错位会影响后续模型理解，必须修；
- 若只是全局章节物理位置在日期小节之后，但内容口径已经同步，可以进入低优先级 polish 池，不阻塞主链；
- 不在封箱前做大范围结构重排，除非已经确认不移动会造成判断错误。

### 2. 已发生的条件句必须升级为当前事实口径

连续文档中常见旧条件句，例如：

- "若收盘跌破 150，是否需要重新评估？"
- "若进入 145—150，是否回到更低位框架？"
- "若 153—155 无法维持，是否……？"

如果最新交易日已经发生了更深层事实变化，例如已经跌破 150、145、138.61，并且收在 145 下方，则不能继续保留这些旧条件句作为当前判断。

必须升级为当前事实口径，例如：

- "07-01 已经收盘跌破 150、145、138.61，当前如何判断？"
- "当前已经跌出 145—150 下方，是否等于底部出现？"
- "153—155 已经失守，后续重新收回才代表修复结构有重建可能。"

处理原则：

- 历史日期小节里的历史条件句可以保留；
- 当前判断区、当前结论、当前框架、底部本卡结论中的条件句必须按最新事实升级；
- 已经发生的事实不能继续写成"如果发生"。

### 3. 估值卡必须防止"便宜幻觉"

估值卡不能因为价格下跌就自动写成估值更安全。

正确区分：

- 价格下移，可以写"静态价格安全边际表面改善"；
- 但若下跌来自外部政策折价、利润预期下修、估值中枢重估、海外业务不确定性上升，则必须同步写"估值重估压力上升"；
- 不能把"跌得多"写成"便宜确认"；
- 不能把"跌到 130+"写成"估值底"；
- 不能把"公司未见自身公告级爆雷"写成"估值风险解除"；
- 不能把"成本摊薄后平均成本更低"写成"补仓更划算"。

正确口径示例：

"价格安全边际表面改善，但政策折价与估值重估压力同步上升。"

### 4. 行情字段返回值必须接受人工基准校验

模型或脚本返回了字段，不代表字段可直接入主链。

2026-07-01 量比案例：

- AKShare 日线接口不提供量比；
- MiMo / 腾讯字段解析曾返回 23.80；
- 同花顺人工核对为 2.34；
- 23.80 判为字段解析异常，不入主链；
- 正式主链采用 2.34，并注明"同花顺人工核对"。

规则：

- 若字段值与人工基准明显冲突，优先相信人工核对；
- 看起来"有来源 / 有 index / 有字段名"的返回值仍可能是错的；
- 腾讯字段、网页字段、接口字段不能盲信固定 index；
- 对异常离谱值必须触发人工复核；
- 字段异常时，写"字段解析异常 / 不入主链"，不要为了凑齐数据强行采用；
- 后续复盘必须注明关键字段来源，尤其是量比、换手、成交额、板块涨跌幅等。

### 5. 封箱前不要被自动补全带偏

封箱前如果主链已通过审计，工具自动补全提出大范围结构移动、重复同步 index、重复改已过关文件，应先暂停。

规则：

- 已过关文件不要重复改；
- 结构重排属于高风险操作，不在封箱前临时做；
- 自动补全建议只能作为提示，不能作为路线；
- 是否执行必须由人工判断；
- 若只是 polish，进入 polish 池，不打断主线。

### 6. 07-01 经验归纳

2026-07-01 阳光电源复盘链路验证了连续文档更新的几个高风险点：

- 正文事实同步不等于标题结构同步；
- 旧条件句会在最新事实发生后变成滞后判断；
- 估值卡容易把"跌得多"误写成"便宜"；
- 工具返回字段如果不经人工校验，可能把异常值写入主链；
- 封箱前自动补全可能诱导不必要的大范围改动。

后续每次大波动日复盘，必须同步审计这些维度。

## 十二、2026-07-02 新增规则｜局部增量更新完成后，必须回扫总控区

v0.3 来源于 2026-07-02 阳光电源加仓节点分析卡批量同步实战。

连续文档更新时，不能只在文件末尾追加最新日期小节。即使新增日期小节本身事实正确，也必须回扫文件中的总控区和当前判断区。

### 必须检查

1. 文件头部当前背景 / 当前状态是否更新到最新交易日；
2. 当前主矛盾是否已经被最新事实改写；
3. 小标题语义是否仍停留在上一交易日；
4. 底部本卡结论是否同步最新口径；
5. 当前判断区是否仍保留旧条件句；
6. 已经发生的事实是否还写成"如果发生"；
7. 旧观察条件是否需要升级为新的观察问题；
8. 动作化表达是否因为旧模板残留重新出现。

### 典型案例

2026-07-02 加仓节点分析卡中，新增 07-02 小节已正确写入"盘中刺破 127.30、最低 127.18、收盘暂守、缩量续跌、动作后置"等核心口径，但文件头部仍一度停留在"截至 2026-07-01"，当前主矛盾仍保留"127.30 是否再次被跌破"，小标题仍出现不适配 07-02 板块环境的旧语境。

正确处理方式：

- "截至日期"必须更新到最新交易日；
- "127.30 是否再次被跌破"在 07-02 已经盘中刺破后，应升级为"是否收盘跌破 127.30 / 是否继续跌破 127.18"；
- 旧标题如果与最新板块环境不匹配，必须同步更新；
- 若只新增日期小节，但未同步头部、主矛盾、小标题和底部结论，视为未完成。

### 规则

- 新增日期小节完成后，必须回扫总控区；
- 当前背景 / 当前主矛盾 / 当前状态 / 当前结论 / 底部本卡结论，与最新日期小节同等重要；
- 不能只做局部增量；
- 如果发现"新段正确、总控区滞后"，必须先修总控区再进入封箱审计；
- 历史日期小节可保留历史事实，但所有当前判断区必须同步到最新交易日。

## 十三、2026-07-02 新增规则｜封箱前必须检查未跟踪新文件是否入暂存区

v0.4 来源于 2026-07-02 阳光电源复盘链路封箱实战。

连续复盘链路中，当日复盘文件通常是新建文件，例如：

- `sungrow/reviews/sungrow_review_2026-07-02.md`

这类文件在 git 中会先显示为 `??` 未跟踪状态。注意：

- `git diff --stat` 不会显示未跟踪文件；
- 新文件如果没有 `git add`，不会进入 commit；
- 只看 `git diff --stat` 容易误判"变更文件齐全"；
- 封箱时必须同时检查 `git status --short --untracked-files=all`；
- 必须确认新建日复盘文件进入暂存区，并在 `git diff --cached --stat` 中显示为新增文件。

### 典型案例

2026-07-02 复盘链路封箱前，审计已通过，且 `sungrow/reviews/sungrow_review_2026-07-02.md` 已存在，但 `git diff --stat` 只显示 7 个已跟踪修改文件。原因是新建日复盘文件仍为 `??` 未跟踪状态，不会出现在 `git diff --stat` 中。若直接提交，会漏掉当天日复盘正文。

### 正确封箱流程

1. 先执行：`git status --short --untracked-files=all`

2. 确认预期新增文件是否存在，例如：`?? sungrow/reviews/sungrow_review_YYYY-MM-DD.md`

3. 执行：`git diff --check`

4. 明确 `git add` 所有预期文件，包括新建文件。

5. add 后必须执行：
   - `git status --short --untracked-files=all`
   - `git diff --cached --stat`
   - `git diff --cached --check`

6. 确认暂存区包含全部预期文件，尤其是新建日复盘文件显示为 `A` 状态。

7. 只有确认 `git diff --cached --stat` 包含新建日复盘文件后，才允许 commit。

### 规则

- 封箱前不能只看 `git diff --stat`；
- 未跟踪文件必须通过 `git status --short --untracked-files=all` 检查；
- 新建日复盘文件必须显式加入 `git add` 文件列表；
- commit 前必须检查 `git diff --cached --stat`，确认暂存区文件数与预期一致；
- 如果预期 8 个文件，cached stat 只有 7 个，必须停止提交；
- 如果出现 `??` 预期文件，不能 commit，必须先确认是否应加入暂存区；
- 封箱判断以暂存区为准，不以工作区 diff stat 为准。

## 十四、2026-07-03 新增规则｜分页接口不能只扫前 N 页

v0.5 来源于 2026-07-03 阳光电源腾讯排行 / qt 量比候选链路复盘。

如果工具数据源来自分页接口，不能固定只扫前 N 页。

### 规则

- 优先使用接口返回的 `total` 计算完整页数；
- `total` 可能是字符串数字，必须安全解析，不能直接假定为整数；
- `total` 缺失时，必须使用空页或少于 `page_size` 作为停止条件；
- 必须设置合理 `safety cap`，避免无限循环；
- 找到目标后必须立即停止翻页；
- 如果全量扫描后仍未找到目标，只能写字段缺失，不能猜；
- 分页修复后必须 review：字符串 `total`、`total` 缺失、目标在后页、最后一页、空页、`page` 自增位置、无限循环保护。

## 十五、2026-07-03 新增规则｜untracked 新文件必须进入封箱清单

v0.6 来源于 2026-07-03 阳光电源复盘链路封箱审计。

### 规则

- 封箱前不能只看 `git diff --stat`；
- 必须执行 `git status --short --untracked-files=all`；
- 新创建的日复盘文件、卡片文件、报告文件若为 `??`，必须纳入封箱清单；
- 如果 `index` 已引用但文件仍为 `??`，属于封箱 P2；
- `git add` 前必须列出预期 `add` 清单；
- 封箱前必须核对未跟踪文件是否已经进入暂存区。

## 十六、2026-07-03 新增规则｜跨日基准必须引用最终口径

v0.7 来源于 2026-07-03 阳光电源复盘链路跨日审计。

### 规则

- “与上一交易日关系”必须引用上一日最终日复盘 / index 的最终口径；
- 不能使用早期工具估算、草稿值或未确认数据；
- 例如 07-03 引用 07-02 成交额时，应以 07-02 最终口径约 108.5 亿为准，不能残留 116.00 亿；
- 同一条链路里，上一交易日的最终口径必须在低位观察卡、持仓卡、风险卡、估值卡、加仓卡和 workbench index 中一致。

## 十八、2026-07-03 新增规则｜已发生条件句必须升级

v0.9 来源于 2026-07-03 阳光电源条件句升级审计。

### 规则

- 已经发生的条件不能继续写成待观察条件；
- 例如 07-03 已经收盘跌破 127.18 / 127.30 后，不能继续写“是否收盘跌破 127.30 / 是否继续跌破 127.18”作为当前未发生条件；
- 必须升级为“是否继续跌破 126.10 / 能否重新收回 126.16、127.18、127.30”；
- 条件句升级后，历史日期小节可以保留旧问法，但当前判断区必须使用新问法。

## 二十、2026-07-03 新增规则｜板块不能粗写为全弱 / 全绿 / 全红

v1.1 来源于 2026-07-03 阳光电源复盘链路板块一致性审计。

### 规则

- 板块不能粗写“全弱 / 全绿 / 全红”；
- 需要按当日人工核对结果写明具体口径；
- 例如 07-03：新能源绿，光伏设备绿，储能红，属于板块表现分化；
- 储能红不足以确认个股风险解除；

- A 股内部文档可使用绿=下跌、红=上涨，但必要时可补一句说明。

## 二十一、2026-07-03 新增规则｜便宜幻觉、成本摊薄幻觉、估值底幻觉与候选量比

v1.2 来源于 2026-07-03 阳光电源估值 / 加仓 / 量比候选链路审计。

### 1. 便宜幻觉与成本摊薄幻觉

- 价格更低 ≠ 更安全；
- 静态估值更便宜 ≠ 估值底确认；
- 成本摊薄更好看 ≠ 动作理由；
- 未见公司自身公告级爆雷 ≠ 风险解除；
- 低位新低点 ≠ 新硬底；
- 收盘价 ≠ 新支撑；
- 加仓卡只能写重新评估条件，不能写动作条件。

### 2. 候选量比规则

- 腾讯实时量比 / 排行 `lb` / `qt index 49` 只能作为候选或交叉验证；
- 同花顺人工核对后才可进入正式主链；
- 候选量比不得直接参与正式字段差异；
- `lb` 与 `qt` 冲突时，必须写“字段解析异常，不入主链”；
- 即使有字段名、index 或网页片段，也不能跳过人工核对直接入链。
